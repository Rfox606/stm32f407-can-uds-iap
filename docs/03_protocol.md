# CAN、ISO-TP与UDS协议接入约定

**当前状态：设计方案，M0尚未接入协议代码。**

采用经典CAN标准帧，500 kbit/s；测试端请求ID为0x7E0，Bootloader响应ID为0x7E8。具体帧格式按ISO-TP与UDS服务约定。

## 计划支持的UDS服务

| 服务号 | 功能 | 实现关注点 |
|---|---|---|
| 0x10 | 诊断会话控制 | 切换编程会话、禁止不合法顺序 |
| 0x22 | 读取数据标识符 | 查询固件版本与状态 |
| 0x34 | 请求下载 | 校验地址、大小和格式，启动更新事务 |
| 0x36 | 传输数据 | 校验块序号、长度与重复块，按偏移写Flash |
| 0x37 | 结束传输 | 确认完整接收并提交固件 |
| 0x31 | 例程控制 | 触发或读取镜像校验结果 |
| 0x11 | ECU复位 | 正响应发送完成后执行复位 |
| 0x3E | 诊断仪在线保持 | 长时间升级时维护会话 |

安全访问0x27暂不纳入基础版；不能宣称实现了认证刷写。UDS状态机必须同时考虑负响应码、P2/P2*超时和0x78等待响应。

## 事务状态
默认会话 → 编程会话 → 下载开始 → 正在接收 → 校验通过 → 提交完成；任何错误或超时应进入明确的中止/恢复路径。

## 关键约束
- UDS的blockSequenceCounter和更新核心的绝对字节偏移是两套概念，需要单独映射。
- 重试时不得重复写入已经确认的Flash数据；重复块的应答要保持幂等。
- Flash擦除期间的总线收发、等待响应和超时需要专门设计。
- ISO-TP必须考虑FF、CF、FC、序号错误、流控超时和缓冲容量。
- 候选开源基础：driftregion/iso14229（MIT），正式接入时固定版本并保存许可证。
