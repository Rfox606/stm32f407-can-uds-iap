# 面试准备：从设计到代码的追问清单

目的不是背名词，而是把每个技术点对应到实际源码、设计取舍与测试依据。

| 追问 | 必须讲清楚的要点 |
|---|---|
| 为什么需要Bootloader？ | 设备不方便接入SWD时通过CAN升级，并保留错误固件下的恢复入口 |
| STM32F407为什么合适？ | Flash空间、CAN控制器和现成开发资源；知道其单Bank局限 |
| 为什么这样分Flash？ | 按扇区擦除；Bootloader、元数据和APP分区隔离；64KB元数据的取舍 |
| 升级中断怎么办？ | 单槽旧APP可能失效，但Bootloader应能重新刷写，不能称为A/B回滚 |
| 为什么最后写magic？ | 避免不完整元数据被认定为已提交 |
| APP有效性怎么判断？ | MSP、Thumb复位向量、镜像范围、元数据CRC和整包CRC |
| CRC和数字签名有什么不同？ | 数据意外损坏检测不等于来源认证 |
| 如何防止擦错扇区？ | Flash端保护、长度边界、目标地址合法性和故障测试 |
| 为什么校验Flash读回数据？ | 兼顾通信错误与写入异常 |
| 0x36重试怎么办？ | 区分UDS块序号与绝对偏移，定义重复请求的幂等语义 |
| ISO-TP四类帧有什么作用？ | SF/FF/CF/FC、序号、BS、STmin和超时 |
| 为什么不能在CAN接收中断里擦除Flash？ | 擦写耗时、收发时序和中断阻塞 |
| APP跳转为何需要MSP、VTOR？ | 切换栈和异常向量、清理中断与SysTick |
| 现阶段到底测了什么？ | 已完成9个主机端场景，未完成实物驱动与物理总线测试 |

## 分级验收
- G0：能画系统架构并定位各模块源码。
- G1：能逐函数讲清更新核心、镜像验证和注入测试。
- G2：具备完整STM32工程、链接映射、Flash驱动及启动代码。
- G3：有正常和异常CAN/ISO-TP/UDS协议测试与日志。
- G4：至少两个实际构造、定位、修复并回归的工程问题。
- G5：README、证据、开源来源与局限全部一致。

不要因为文档写了某个功能，就把它算作通过验收。
