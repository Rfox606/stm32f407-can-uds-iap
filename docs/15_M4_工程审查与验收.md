# M4：工程审查与最终验收

日期：2026-11-24。依赖M3 PR #7；当前M4独立开发分支`feature/m4-hardening-interview`。项目以STM32F407VGT6、单APP槽、经典CAN 500 kbit/s、ISO-TP与UDS编程子集为设计基线。

## 一、评价方法：不把构建通过误认为上板运行

按下列证据层次逐项审查：
1. **源码存在且实际接通**：核对调用路径和构建脚本，不以README中的功能声明代替实现。
2. **实际软件执行**：C/CMake单元测试和Python到真正C版UDS更新核心的跨进程调用。
3. **ARM目标构建**：检查arm-none-eabi-gcc编译/链接、向量表入口、`size`和MAP。
4. **设计推导**：使用ST原厂芯片资料与ISO-TP协议资料，注明理论假设。
5. **硬件实证（本项目缺失）**：真实CAN、Flash擦写、SRAM软件复位保持和断电行为未测试，不能因前四项通过而标记成功。

## 三、M4实质性修复：先有CAN TXOK，后执行危险操作

### 发现的缺陷

M3的`uds_boot_request()`在接到`0x34`后设置`busy_erase=1`，随后Bootloader尝试执行`isotp_send(0x7F 0x34 0x78)`。如果发送邮箱忙或该发送调用失败，原主循环仍可能在`bxcan_tx_complete()==1`（此时**不存在待发送帧，也可返回1**）的情况下擦除Flash。

APP接到`10 02`后先把交权标志置位，如果`50 02`从未送入邮箱，原主循环同样可能提前软件复位。这违背“先告知诊断端，再进行Flash操作/软件复位”的设计约束。

### 修改的具体实现

- 新增`protocol/include/reply_gate.h`、`protocol/src/reply_gate.c`，缓存最多7字节的单帧UDS响应。
- **提交发送**：如果CAN邮箱忙或提交失败，不丢弃响应；下次主循环重试，不授权后续动作。
- **发送确认**：仅在响应确实已提交发送、并且bxCAN报告TXOK后，`reply_gate_take_ack()`才返回1且只能取一次。
- Bootloader的`0x34`逐扇区擦除、`0x37`完成校验提交、`0x31`完整校验以及`0x11`复位均需消耗对应的确认标志。
- APP交权也必须在`50 02`确认后才能执行`SYSRESETREQ`。
- CMake与ARM交叉构建同步加入新模块；未留下只在主机端存在、ARM固件未链接的模块。

### 验证

`tests/test_reply_gate.c`以真实`isotp_send` + 可控的CAN发送回调进行三组软件注入，分别覆盖：邮箱繁忙、报文提交失败、CAN未TXOK、TXOK后单次授权、APP交权不能提前复位、非法响应长度拒绝。测试不依赖寄存器或开发板，是**协议与调度级**验证。

> 这里的TXOK意味着CAN控制器报告该帧传输成功，**不意味着上位机UDS应用已经处理了这条响应**；对于掉电、应用层丢失和总线重发仍必须依赖上位机超时策略与完整性检查。

## 四、剩余风险，不隐瞒也不夸大

| 风险与优先级 | 现状及影响 | 验证或缓解路径 |
|---|---|---|
| P0：真实Flash擦除与UDS P2*时序 | STM32F407单Bank Flash可能在擦写时阻塞取指和通信处理；`0x78`分阶段设计仍未证明最坏擦除时间小于P2* | 对照芯片资料按供电条件计算，实物上测扇区擦除最长时间、应答间隔与CAN状态 |
| P0：软件交权上板行为 | 双字SRAM标志与RCC复位原因逻辑已编译和单测，但未验证指定开发板软件复位后RAM保持 | 实物记录上电/复位原因、手动按键、APP→Bootloader和返回APP |
| P1：CAN错误后的恢复 | bxCAN发送错误/总线关闭时目前**保守停止推进**，未做成熟的自动重连、失败状态恢复 | 增加显式报错、软复位/超时恢复策略，再用真实CAN故障注入核对 |
| P1：非认证刷写 | 没有0x27安全访问、签名、加密或防降级 | 个人项目不声称车规量产或受信任的安全升级 |
| P1：APP版本一致性 | F150读已提交元数据版本，不保证与APP编译时的静态版本字段相同 | 构建时引入统一版本常量或镜像头比对 |
| P2：全协议一致性 | ISO-TP/UDS是必要子集，未覆盖全部寻址模式和参数 | 不宣传为完整标准栈；如产品化可替换成熟协议栈 |
| P2：性能实测 | 目前只有理论CAN帧数/构建体积，没有实物升级总时长 | 使用`tools/estimate_upgrade.py`给理论下界，真实设备测时间并单独归档 |
