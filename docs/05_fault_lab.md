# 故障注入与根因定位记录

本项目使用可复现的故障注入训练调试能力。须区分实际运行日志、静态推导与尚未执行的板级测试。

## A：固件内容被破坏（已测试）
正常写入并提交固件后，故意翻转模拟Flash内的一个字节。启动时元数据和向量表仍可能合法，但整包CRC不符，Bootloader应选择恢复模式。
对应：tests/test_boot_core.c中的test_corrupt_existing_image。

## B：升级下载中断（已测试）
开始下载256字节固件，仅写入128字节后丢弃更新器运行时状态，模拟复位；元数据无有效提交标记，启动进入恢复模式。
对应：test_interrupted。只模拟逻辑复位，不是实际断电波形或Flash擦写中断。

## C：提交标志写入失败（已测试）
让模拟Flash在写入magic时返回失败，检查Bootloader是否仍拒绝跳转不完整镜像。
对应：test_commit_failure。

## D：APP跳转异常（待实现）
可主动构造错误VTOR、残留SysTick或MSP切换顺序不正确的问题。应收集链接映射、汇编、寄存器和实际运行证据后再写根因报告；未上板不能声称真实触发HardFault。

## E：ISO-TP流控超时（待实现）
通过延迟或撤销FC、篡改CF序号、设置非零STmin等故障，定位发送或接收状态机如何退出。

## 统一问题记录格式
1. 版本、环境与触发方式；
2. 实际现象及最小复现步骤；
3. 排除过程与日志；
4. 根因和被排除的假设；
5. 修改的代码与设计依据；
6. 回归测试及结果；
7. 不能由当前证据证明的内容。
